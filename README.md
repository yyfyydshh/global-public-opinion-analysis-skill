# 全球舆情与品牌口碑分析 Skill

面向产品、品牌和商业事件的全球公开网页舆情分析工作流。它将公开网页检索结果按可审计的流程进行采集、去重、质量筛选、结构化分析，并生成可追溯的 Markdown 报告、Excel 数据包，以及可选的离线 HTML 报告。

> 本仓库不包含 API Key、授权请求头或账号额度信息。连接器配置仅提供环境变量占位符；请在本地或密钥管理服务中设置凭据，绝不要提交真实密钥。

## 能解决什么问题

- 产品 VOC：功能体验、痛点、需求、购买决策、替代选择和竞品口碑。
- 品牌与事件声誉：产品召回、售后争议、消费者投诉、商业诉讼、监管或品牌危机等商业议题。
- 上市与新品反馈：围绕性能、价格、服务、生态、可靠性等维度的公开反馈梳理。
- 证据驱动的行动建议：每条关键事实、数据、案例和建议都应能追溯到原始网页 URL。

不适用于政治人物、政党和选举、主权或地缘争议、战争与军事行动、武器或情报等敏感主题。此类主题会在检索前被拦截，不会发起采集。

## 核心能力

1. **两类分析报告**
   - `product_voc`：适用于具体产品、型号、功能、使用体验、购买决策和竞品比较。
   - `event_reputation`：适用于品牌整体口碑、企业危机、召回、售后问题、商业诉讼、监管和一般商业事件。
2. **可控采集范围**：支持时间窗、目标有效数据量、市场/语言、竞品及关注维度。默认最近 30 天、全球覆盖、3 个检索批次；最长可扩展至最近 90 天，目标有效记录数可设为 1–1000。
3. **采集前检查**：验证只读检索连接器、主题范围和来源策略；每次检索前生成一次性采集许可。
4. **数据清洗与审计**：保留检索上下文、时间戳和原始 URL；执行规范化、去重、广告过滤、相关性与质量评分，并保留被排除记录及原因。
5. **正式报告门槛**：至少 100 条有效记录、5 个来源域名、2 种来源类型，并通过来源策略审计；未达标时只交付数据包、覆盖缺口和续采建议，不把不足样本包装成正式结论。
6. **多格式交付**：Excel 数据包包含 Summary、Raw、Cleaned、Excluded、Query Log、Dictionary 六个工作表；正式报告为 Markdown；经用户确认后可生成无远程脚本的单文件 HTML。

## 安装与连接器配置

本 Skill 需要一个兼容 MCP 的**只读**公共网页检索连接器。该连接器至少应提供与下列能力等价的工具：

- `list_platforms`
- `search_platform_content`

复制示例配置，并在运行环境中设置变量：

```powershell
Copy-Item mcp.example.json mcp.json
$env:OCTOPARSE_API_KEY = "在此处仅为当前会话设置你的密钥"
```

`mcp.json` 已在 `.gitignore` 中忽略。若你的 MCP 宿主使用不同的配置目录，请将示例内容放到该宿主要求的位置。生产环境建议通过操作系统环境变量或密钥管理服务注入 `OCTOPARSE_API_KEY`。

## 使用方式

直接描述要分析的产品、品牌或商业事件即可。为了获得更稳定的结果，建议同时说明时间、目标数据量、市场/语言、竞品和关注维度。

### 示例

```text
分析 iPhone 17 最近一周的全球产品舆情，重点关注性能、安全、价格、开发者体验和主要竞品。
```

```text
分析某消费电子品牌产品召回事件最近 30 天的舆情：梳理已确认事实、消费者诉求、品牌回应、风险等级和未来 48 小时行动优先级。
```

### 可复制模板

```text
分析【主题】在【时间范围】内的全球舆情，需【数据量】条有效数据，重点关注【市场/语言】、【竞品】和【关注维度】。
```

| 参数 | 是否必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| 分析主题 | 是 | 产品、型号、品牌或商业事件 | iPhone 17；某品牌召回事件 |
| 时间范围 | 否 | 未填写时默认最近 30 天；最多 90 天 | 最近 7 天；2026 年 7 月 |
| 有效数据量 | 否 | 未填写时默认 3 批；可指定 1–1000 条清洗去重后的有效记录 | 200 条 |
| 市场或语言 | 否 | 聚焦国家、地区或语言 | 中国、美国、欧洲；中英文 |
| 竞品 | 否 | 指定比较对象；未指定时可从数据中识别候选项 | Galaxy；旗舰机 |
| 关注维度 | 否 | 产品功能、服务、价格、风险或业务问题 | 影像、续航、价格、售后 |

## 一次任务如何运行

1. 验证连接器已配置且仅提供只读检索能力。
2. 判断主题是否在允许的商业分析范围内；不允许时停止，不检索。
3. 锁定来源策略和运行清单，生成针对主题的检索词。
4. 分批采集公开网页内容。首批得到合格数据后，先展示 5–8 条候选预览（标题、日期、来源、摘要和链接）。
5. 自动完成本轮剩余批次，对记录进行时间校验、去重、筛选和来源审计。
6. 检查正式报告门槛：未通过时交付数据包与续采建议；通过时输出正式分析报告与 Excel。
7. 正式报告完成后，仅在用户明确需要时生成可视化 HTML。

预览只用于确认主题相关性和来源质量，不等于最终结论。最终有效记录数通常会小于原始检索结果数。

## 报告内容

### 产品 VOC 报告

覆盖管理摘要、趋势与口碑结构、产品/服务体验维度、使用场景、用户需求、购买决策、核心痛点、可验证优势、竞品与替代选择、未满足需求，以及产品/营销/渠道/客服行动建议。证据不足时会明确标记“未发现可验证证据”，不会为了填满模块而推断。

### 事件与品牌声誉报告

覆盖执行摘要、当前阶段和最高优先事项；已确认事实与未证实信息的分层；事件时间线、证据等级、议题、情绪、立场、公众诉求、媒体叙事、利益相关方、已有回应质量、五级风险判断，以及升级/降温信号和分阶段行动建议。

## 输出与数据边界

| 交付物 | 内容 | 出现条件 |
| --- | --- | --- |
| 数据预览 | 5–8 条候选记录及真实链接 | 首批或前两批获得合格数据后 |
| Excel 数据包 | Summary、Raw、Cleaned、Excluded、Query Log、Dictionary | 完成本轮采集与清洗后 |
| Markdown 正式报告 | 产品 VOC 或事件/品牌声誉分析 | 达到 100 条有效记录、5 个域名、2 种来源类型并通过证据校验 |
| 可视化 HTML | 摘要卡、目录、图表、表格、真实证据链接；可离线查看 | 正式报告完成且用户明确确认 |

- 网页记录数量仅代表本次检索覆盖内的内容量，不代表全网声量、市场份额、真实用户数或人群渗透率。
- 上游未返回的作者、粉丝、点赞、评论、转发、观看、ASR/OCR 或人口属性会保持空值，绝不推测。
- 不伪造事实、引文、来源、日期、竞品数据、因果关系或风险分数。
- 平台可用性和实际来源取决于每次任务的连接器响应与公开网页状态。

## 安全与隐私

- 仅使用公开网页和配置为只读的连接器。
- API Key 只应存在于本地环境变量或密钥管理服务；不要写进配置文件、日志、报告、Excel 或版本库。
- `mcp.example.json` 中的 `${OCTOPARSE_API_KEY}` 是字面量占位符，不是有效凭据。
- 运行脚本会对常见凭据和认证头进行掩码；这不能替代正确的密钥管理。
